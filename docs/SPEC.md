## 2. 実現性の検討：家族共有と添付

### 2.1 Google カレンダーの添付の仕組み（確認結果）
- **ご認識のとおり、Google カレンダーの添付は Google ドライブのファイルだけ**です。
  - Web 版で PC のファイルを選んだ場合も、内部ではドライブにアップロードされてから添付されます。
  - Android の公式アプリは、添付の表示とドライブでの起動はできますが、添付の追加はできません（Web 版を使う必要があります）。
- 添付の実体は、予定データの `attachments` に入るドライブファイルの参照（`fileId`、`fileUrl`、タイトル、MIME タイプ）です。1 予定あたり最大 25 件です。
- **重要**：カレンダーを共有しても、**ドライブのファイルの閲覧権限は自動では付きません。** Web 版では、添付時に「ゲストにファイルへのアクセス権を付与しますか？」と確認が出ます。共有カレンダーのメンバーには、ファイルごとに権限を付ける必要があります。

### 2.2 結論：実現可能
端末内のファイルを選ぶ → アプリがドライブにアップロード → 予定に添付 → 閲覧できる人に自動で権限を付与、という流れで、ご希望の形が実現できます。

| 閲覧する人 / 方法 | 見られるか | 条件 |
|------------------|-----------|------|
| 家族：このアプリ | ○ アプリ内で表示（PDF はアプリ内ビューア） | ドライブの閲覧権限（アプリが自動で付与）＋読み取りスコープ（§2.3） |
| 家族：公式 Google カレンダー（Android / iOS / Web） | ○ 添付をタップするとドライブで開く | ドライブの閲覧権限（アプリが自動で付与） |
| 予定のゲスト（カレンダー共有外の人） | ○ | 添付時に「ゲストにも共有」をオン（初期値。Web 版と同じ動作） |
| 一般公開カレンダーを見る人 | × ファイルは公開しない | 安全のため、意図せず公開しない（§6.4） |

### 2.3 技術的な注意点：ドライブのスコープ
- `drive.file` スコープで読み書きできるのは、**自分がこのアプリで作ったファイルだけ**です。家族がアップロードしたファイルは、権限があってもこのスコープでは取得できません。
- そこで **`drive.readonly`** スコープを追加し、共有されたファイルをアプリ内で表示・キャッシュできるようにします。
  - `drive.readonly` は Google の「制限付きスコープ」です。家族利用（100 人以下）の未審査アプリなら利用できますが、ログイン時に「確認されていないアプリ」の警告が出ます。
  - 一般に公開するなら、セキュリティ審査が必要になります。
- 家族が `drive.readonly` を許可しなかった場合は、ドライブアプリかブラウザで開く方式に切り替えます。閲覧はできますが、アプリ内でのプレビューとオフライン保存はできません。

## 3. アーキテクチャ

### 3.1 データ取得方式（v0.2 から継続）

| 用途 | 仕組み |
|------|-------|
| 予定の表示（各ビュー・ウィジェット） | CalendarContract（`Instances`）。オフラインで動き、高速 |
| 予定の登録・変更・削除 | CalendarContract（`Events` / `Reminders` / `Attendees`）。OS が Google と同期する |
| カレンダーの作成・削除・名前変更・色変更・表示選択 | Calendar API（`calendars`、`calendarList`） |
| 共有設定 | Calendar API（`acl`） |
| 予定への添付 | Calendar API（`events.patch`、`supportsAttachments=true`） |
| 添付ファイルの保存・権限付与・取得 | Drive API（`files`、`permissions`、`changes`） |

### 3.2 アカウント
- 端末に登録された Google アカウントのうち、カレンダー同期が有効なものを自動で検出する（CalendarContract の `ACCOUNT_NAME` / `ACCOUNT_TYPE=com.google`）。
- API のアクセス許可はアカウントごとに取る（`AuthorizationRequest.setAccount()`）。許可は Android の仕組み側が保持し、アプリはパスワードやトークンを保存しない。
- 端末にないアカウントは、ドロワーの「アカウントを追加」から Android のアカウント追加画面を呼び出して登録する。
- 要求するスコープ：
  - `calendar`
  - `drive.file`
  - `drive.readonly`（任意。断られた場合の動作は §2.3）

### 3.3 技術スタックとモジュール構成
v0.2 と同じ（Kotlin、Compose M3、Hilt、Room、WorkManager、Glance）。v0.3 では `core/google` にアカウント管理（`AccountRegistry`）を追加し、`core/attachments` に権限同期（`PermissionReconciler`）を追加する。

## 4. 画面と操作

### 4.1 画面構成
```
メイン（日 / 週 / 月 / 予定 をワンタッチ切替）
 ├ 下部シート（予定の詳細・作成・編集。全ビュー共通）
 ├ ドロワー：アカウント切替、カレンダー一覧（表示選択）、設定への入口
 ├ 検索
 ├ カレンダー管理 → 共有と権限
 ├ 設定 → 添付・同期 / 通知 / 表示 / アカウント / アップデート
 └ オンボーディング（初回のみ）
```

### 4.2 下部シート（全ビュー共通の中心となる操作）
「日・週・月のどこで対象を選んでも、下からシートが出て、その場で入力できる」形に統一する。

| どこをタップしたか | シートの内容 | 初期の高さ |
|-----------------|-------------|-----------|
| 月表示の日付 | その日の予定一覧と、先頭に「この日に予定を追加」の入力欄 | ハーフ |
| 週表示・日表示の空いている時間 | **クイック作成**：タイトル入力（キーボードが自動で開く）、日時、カレンダー、添付、［保存］［詳細］ | ハーフ（キーボードの上） |
| 週表示・日表示の空き時間をドラッグ | 範囲を選んだ状態でクイック作成 | ハーフ |
| 任意の予定 | 予定の詳細。各項目をタップするとその場で編集でき、添付の追加もできる | ハーフ |
| ＋ボタン | クイック作成（次の正時から 1 時間、前回使ったカレンダー） | ハーフ |

- 高さは 3 段階：ピーク（1 行）／ハーフ／全画面。上にスワイプすると全画面の編集画面（v0.2 の「予定の編集」と同じ内容）になる。
- シートを開いている間も、上半分のカレンダーは操作できる。別の日をタップすると、シートの中身がその日に切り替わる。
- 入力中に下へスワイプして閉じた場合：タイトルが空なら破棄する。入力があれば「下書きを破棄しますか？」と確認する。
- 選んだ対象（日付セル、時間枠、予定）はカレンダー上で強調表示し、シートとの対応が分かるようにする。

### 4.3 ワンタッチ表示切替
アプリバーの下に［日］［週］［月］［予定］を常に表示する（「3日」も追加できる）。基準日は切り替えても保ち、最後に使った表示を覚えておく。

### 4.4 月表示
- 週単位の縦スクロール（標準）。月単位の横スワイプにも切り替えられる。
- 月の境目には区切り線と月ラベルを付ける。予定は色付きのチップで表示し、添付付きの予定にはクリップのアイコンを付ける。

### 4.5 週表示・日表示
- 時間軸のグリッド（初期表示は現在時刻の 1 時間前から）。終日予定の帯と現在時刻の線を表示する。
- ピンチで時間の幅を拡大・縮小できる。予定は長押ししてドラッグすると移動し、端をドラッグすると長さを変えられる。

### 4.6 予定一覧（スケジュール）
今日から先へ続く無限リスト。月の見出しを付け、予定のない日は詰めて表示する。

### 4.7 ドロワー（アカウントとカレンダー）
- 上部にアカウントのアバターを並べる。［すべて］と各アカウントを 1 タップで切り替える（表示を絞り込む）。
- その下に、アカウントごとのカレンダーをチェック付きで一覧表示する。チェックは Google の表示設定と同期する。
- 新規作成の初期カレンダー：絞り込み中のアカウントのメインカレンダー。［すべて］のときは前回使ったカレンダー。

### 4.8 カレンダー管理・共有設定
v0.2 の §4.6・§4.7 と同じ。メインカレンダーには削除メニューを出さない。共有を変えると、添付ファイルの権限も自動で追従する（§6.3）。

## 5. 添付ファイル：保存と同期

### 5.1 流れ
1. 端末内のファイルを選ぶ（ファイル選択、カメラ、他アプリからの共有のいずれか）。
2. ローカルフォルダにコピーし、すぐに「アップロード中」と表示する。
3. ドライブにアップロードする（再開可能なアップロード）。
4. `events.patch` で予定の `attachments` に追加する。
5. 閲覧できる人に権限を付与する（§6）。

### 5.2 ドライブ上の配置
```
マイドライブ/
└─ Calendar 添付/
   └─ <カレンダー名>/                 … カレンダーごとのフォルダ。共有メンバーとフォルダ単位で共有
      └─ 2026-11/
         └─ 20261117_定例ミーティング_k3f9/
            └─ 議事録_1117.pdf
```
- フォルダはアップロードした人のマイドライブに作られ、容量もその人の分を使う。
- 各ファイルには `appProperties` で `calendarId`、`eventId`、範囲（この回 / シリーズ）を記録する。

### 5.3 ローカルフォルダ
- ドライブと同じ構成で、キャッシュとして保存する。自分の添付も家族の添付も同じ場所に置く。
- 自分の添付は常にローカルに残す。家族の添付は、開いたときに取得する（設定で「自動ダウンロード」「Wi-Fi のみ」を選べる）。
- 保存先は Storage Access Framework で選ぶ。初期値は `Documents/Calendar`。

### 5.4 同期処理
v0.2 の §5.4 を継続する。追加点：
- 予定の `attachments` を同期の基準にする。家族が追加・削除した添付は、CalendarContract の同期で予定が更新されたときに、API で読み直して反映する。
- 添付を削除したとき：自分のファイルなら紐付けを外してドライブのゴミ箱へ移す。家族のファイルなら紐付けだけ外し、ファイルは持ち主のドライブに残す。

## 6. 家族共有と添付の権限

### 6.1 基本方針
**「予定の詳細を見られる人は、添付も見られる」** を自動で保つ。

### 6.2 権限の対応

| カレンダーの ACL | ドライブのフォルダ権限 |
|-----------------|---------------------|
| `owner` / `writer` / `reader` | 閲覧者（`reader`） |
| `freeBusyReader`（時間のみ） | なし（予定の詳細も見えないため） |
| `default`（一般公開） | 付与しない（シートに警告を出す） |
| ACL の種類が `group`（Google ファミリーグループなど） | 同じグループのメールアドレスに付与 |
| 予定のゲスト（ACL 外） | 「ゲストにも共有」がオンなら、ファイルごとに閲覧者を付与 |

- 書き込み権限のある家族にも、ドライブでは閲覧権限だけを付ける。こうすることで、他人のドライブ上のファイルを直接削除できないようにする。
- 権限付与の通知メールは送らない（`sendNotificationEmail=false`）。

### 6.3 権限の追従
- アプリで共有メンバーを変更したとき：その場でフォルダの権限を更新する。
- Web 版などアプリ外で ACL が変わったとき：同期時（6 時間ごと、起動時）に `acl.list` と見比べて修正する。修正はフォルダの持ち主の端末が行う。
- 家族を共有から外したとき：フォルダの権限も外す。

### 6.4 安全策
- カレンダーが一般公開でも、添付は公開しない。
- 権限付与に失敗したとき（相手が Google アカウントではない、など）は、添付に「一部の人が閲覧できません」と表示し、詳細を確認できるようにする。

## 7. ウィジェット（3 種類）

| 種類 | 推奨サイズ | 表示 | 操作 |
|------|-----------|------|------|
| 月 | 4×4（3×3〜） | 月グリッドと予定チップ | ◀▶ で月を移動。日付タップでアプリの月表示を開き、その日のシートを出す。＋ で作成 |
| 週 | 4×4（4×2〜） | **時間軸付き** 7 列。上に終日予定の帯 | ◀▶ で週を移動。空き時間をタップするとクイック作成、予定タップで詳細 |
| 日 | 4×3（2×2〜） | **時間軸付き**の 1 日のタイムラインと現在時刻の線。小さいサイズでは次の予定だけを表示 | ◀▶ で日を移動、予定タップで詳細 |

- 共通：表示するカレンダー、アカウント、背景の透明度、テーマを設定できる。添付付きの予定にはクリップのアイコンを付ける。
- 時間軸の表示範囲：既定では現在時刻を基準に、表示できる時間だけを出す。設定で固定範囲（例：7〜22 時）にもできる。
- 更新のタイミング：カレンダーが変わったとき、日付が変わったとき、15 分ごと（現在時刻の線のため）、アプリで編集したとき。

## 8. 通知
- OS から届く `EVENT_REMINDER` を受け取って通知を出す。操作は［開く］［スヌーズ］［地図］。通知はアカウントごとにまとめる。
- 公式の Google カレンダーと二重に通知されないよう、設定でオン・オフを切り替えられる。
- 追加：家族が予定や添付を追加したときに通知する機能（任意。初期値はオフ。P5）。

## 9. UX 補完（プロダクトデザイン観点）

### 9.1 オンボーディング（初回 4 ステップ）
1. 「カレンダーへのアクセス」を許可（OS の権限ダイアログ）。拒否された場合は、説明と再要求の画面を出す。
2. アカウントを確認：検出したアカウントの一覧から、使うものを選ぶ。
3. Google への連携（Calendar / Drive）：用途を説明してから同意画面を出す。「確認されていないアプリ」の警告の進め方を図で案内する。スキップした場合は、予定の閲覧と編集だけで使える。
4. 通知の許可。添付の保存先は、初めて添付するときに尋ねる（最初に聞くことを減らす）。

### 9.2 操作の原則
- **削除は確認ダイアログではなく、取り消せるスナックバー**（5 秒）で行う。Google カレンダーと同じ。ただし、カレンダー自体の削除と共有の解除は確認を必須にする。
- 作成時の初期値：開始は次の正時（タップした場合はその時間枠）、長さは 1 時間（設定で変更可）、カレンダーは前回使ったもの。
- 予定の移動や長さの変更、週スクロールが週の区切りに揃うときは、触覚フィードバックを返す。
- 戻る操作の順序：シート全画面 → ハーフ → 閉じる → 今日へ戻る。今日を表示しているときだけアプリを終了する。

### 9.3 家族利用への配慮
- 予定の詳細に **「作成：○○ ・ 最終更新：○○」** を表示する。誰が入れた予定か分かるようにするため。
- 添付には追加した人のアバターを表示する。
- 家族が同時に編集した場合：保存時に、相手の変更を上書きしてよいか確認する。

### 9.4 状態の表示
- オフラインのときは上部に細い帯を出す（「オフライン ・ 変更は接続後に同期」）。
- 同期中の添付には進捗、失敗したものには［再試行］を表示する。
- 予定がないときは、その旨を一言とクイック作成の入口だけ表示する（イラストは使わない）。
- 読み込み中は、ちらつかないよう骨組みだけを先に表示する。

### 9.5 アクセシビリティ
- タップできる範囲は 48dp 以上。文字サイズは 200% まで崩れないようにし、TalkBack で予定の内容が読み上げられるようにする。
- 色だけで情報を伝えない：添付はアイコン、予定の状態は線種や透明度でも示す。
- 文字と背景のコントラストは 4.5:1 以上。ダークテーマに対応する。

### 9.6 日本向けの配慮
- 祝日を表示する（日本の祝日カレンダーを初期で購読し、日付の色を変える）。日曜は赤、土曜は青。
- 和暦表示、六曜、週番号は設定でオンにできる（初期値はオフ）。

## 10. 権限

## 14. オーナー作業
1. Google Cloud プロジェクトの準備：Calendar API と Drive API を有効にする。OAuth 同意画面を「外部」で作り、`calendar`、`drive.file`、`drive.readonly` を登録し、公開ステータスを「本番環境」にする。
2. Android 用 OAuth クライアントを登録する：`io.github.barista9409.calendar` と SHA-1（debug 用と release 用）。SHA-1 は P0 で伝える。
3. GitHub Secrets に署名鍵の情報を登録する（P0）。
4. 家族の端末で、提供元不明のアプリのインストールを許可する。

### リリース手順
1. GitHub Secrets に `KEYSTORE_BASE64`、`KEYSTORE_PASSWORD`、`KEY_ALIAS`、`KEY_PASSWORD` を登録する（`RELEASES_REPO_TOKEN` は登録済み）
2. `v0.1.0` のようなタグを push すると、`release.yml` が次の処理を行う
   - 署名付き APK をビルドする
   - `calendar-releases` に Release を作り、APK を添付する
   - `update.json` を更新する
3. 初回だけ、Release ページから APK を端末にダウンロードしてインストールする。以降はアプリ内アップデートで更新できる
